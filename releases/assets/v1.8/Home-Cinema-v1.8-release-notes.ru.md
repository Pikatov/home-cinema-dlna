# Home Cinema v1.8 (2026-05-31)

Home Cinema 1.8 делает две вещи: надёжнее запускает фильмы на телевизоре и даёт более понятное окно управления на macOS.

## Что заметно сразу
- **Новый macOS-интерфейс.** Окно стало спокойнее и полезнее: большой блок `ON AIR`, список активных стримов, понятный статус сервера и аккуратный список сохранённого прогресса.
- **Видно, что сейчас играет.** Приложение показывает активные сессии: название, устройство, тип потока (`DIRECT`, `TRANSCODE`, `RESUME`) и текущий таймкод.
- **Сброс прогресса можно отменить.** После reset появляется undo-баннер на 5 секунд.
- **Тяжёлые MKV чаще запускаются на ТВ.** Для больших файлов и HEVC/HDR MKV сервер автоматически предлагает совместимый TV-поток через `ffmpeg` раньше оригинального файла.

## Воспроизведение и DLNA
- TV-поток стал аккуратнее объявлять длительность: сервер отправляет `Content-Duration`, `TimeSeekRange.dlna.org`, `X-Content-Duration` и `X-AvailableSeekRange`.
- Для TV-потока включён DLNA time-seek (`DLNA.ORG_OP=10`), и сервер понимает входящие `TimeSeekRange.dlna.org` запросы.
- Одновременно запускается ограниченное число ffmpeg-транскодов (`--max-tv-streams`, по умолчанию 1). Если ТВ переподключается или делает seek, старый ffmpeg-процесс того же клиента отменяется.
- TV-поток теперь отдаёт AC3-аудио и более широкий VBV-буфер по умолчанию (`40 Mbps`), что лучше подходит для телевизоров и динамичных сцен.
- Честное ограничение: некоторые ТВ всё равно показывают ffmpeg/MPEG-TS поток как `mpg` или рисуют конец как `0:00`. Сервер отдаёт длительность и time-seek, но итоговое отображение зависит от DLNA-клиента.

## Прогресс просмотра
- Прогресс сохраняется и по байтам, и по секундам, когда это возможно.
- Ранние probe-запросы от телевизора меньше рискуют затереть нормальный прогресс.
- Если фильм удалили из медиатеки, его прогресс вычищается на старте, при смене папки и затем периодически раз в час.
- После рестарта сервер может восстановить длительность из сохранённого прогресса, пока `ffprobe` ещё не успел прогреть кеш.

## Сервер
- Добавлен `/stats`: лёгкий endpoint для UI, который отдаёт активные стримы без лишних данных.
- `/video/` остаётся прямой отдачей файла с HTTP `Range`.
- `/tv/` отдаёт совместимый ffmpeg-поток для телевизоров, которым тяжело открыть оригинальный файл.
- `/resume/` отдаёт виртуальный хвост исходного файла от сохранённой позиции с корректными `Content-Range`, `Content-Length` и DLNA-заголовками.
- SSDP shutdown стал аккуратнее: при завершении сервер отправляет `ssdp:byebye`, чтобы ТВ быстрее убирал старый сервер из списка.

## Требования
- macOS app: **macOS 14 Sonoma или новее**.
- Сервер: Go `1.26+` для сборки из исходников.
- `ffprobe` рекомендуется для длительности и таймкодов.
- `ffmpeg` нужен для TV-потока; если его нет, сервер отключит этот режим и продолжит работать с прямой отдачей файлов.

## Обновление
- Формат пользовательских данных не менялся.
- Для обновления замените `.app` или standalone server binary.
- После обновления лучше заново открыть Home Cinema на ТВ, чтобы телевизор сбросил старый DLNA-кеш.

## Assets
- `Home-Cinema-1.8-macOS-app.zip` — готовое macOS-приложение `Home Cinema.app` со встроенным сервером.
- `Home-Cinema-1.8-macOS-server.zip` — standalone universal server binary для запуска без GUI.
